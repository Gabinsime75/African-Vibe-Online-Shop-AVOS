# Prometheus Module

## Overview

The Prometheus module deploys the **Phase 1 monitoring foundation** for the CloudHustler Commerce Platform using the **kube-prometheus-stack** Helm chart.

This module establishes the core Kubernetes monitoring platform that will be extended during later implementation phases.

The deployment includes:

- Prometheus Operator
- Prometheus Server
- Alertmanager
- kube-state-metrics
- Prometheus Node Exporter
- Kubernetes default alerting rules
- Kubernetes default recording rules

Grafana, dashboards, ServiceMonitors, PodMonitors, Istio metrics, Karpenter metrics, and application monitoring are intentionally excluded from this phase.

# Components

## Prometheus Operator

Responsible for managing all Prometheus custom resources including:

- Prometheus
- Alertmanager
- ServiceMonitors
- PodMonitors
- PrometheusRules

---

## Prometheus Server

Collects and stores Kubernetes metrics.

Configured with:

- Persistent storage
- Metric retention
- Resource limits
- Automatic service discovery

---

## Alertmanager

Receives alerts generated by Prometheus.

Provides:

- Alert grouping
- Alert deduplication
- Alert silencing
- Notification routing

Notification integrations will be configured in a later phase.

---

## kube-state-metrics

Exposes Kubernetes object metrics including:

- Deployments
- Pods
- StatefulSets
- DaemonSets
- Jobs
- Nodes
- Namespaces

---

## Prometheus Node Exporter

Collects operating system metrics from every Kubernetes node.

Examples include:

- CPU utilization
- Memory usage
- Filesystem utilization
- Network statistics
- Disk I/O

---

## Kubernetes Monitoring Rules

The deployment enables the default Kubernetes monitoring rules provided by the kube-prometheus-stack chart.

These include recording rules and alerting rules for common Kubernetes conditions.

# Phase 1 Scope

This module implements only the monitoring foundation.

Included:

- Prometheus Operator
- Prometheus Server
- Alertmanager
- kube-state-metrics
- Node Exporter
- Kubernetes monitoring rules

Not included:

- Grafana
- Dashboards
- Data sources
- ServiceMonitors for applications
- PodMonitors
- Istio monitoring
- Karpenter monitoring
- Application monitoring

These components will be implemented during subsequent phases.

# Troubleshooting

## Pods not starting

```bash
kubectl get pods -n monitoring

kubectl describe pod <pod-name> -n monitoring

kubectl logs <pod-name> -n monitoring
```

---

## Helm deployment failed

```bash
helm status kube-prometheus-stack -n monitoring
```

Review Terraform output for the failing resource.

---

## Prometheus CRDs missing

```bash
kubectl get crds | grep monitoring.coreos.com
```

If the CRDs are not present, verify the Helm release completed successfully.

---

## Persistent Volume Claims pending

```bash
kubectl get pvc -n monitoring
```

Verify:

- StorageClass exists
- EBS CSI Driver is running
- Persistent volumes can be provisioned

---

## Operator not creating Prometheus

```bash
kubectl logs deployment/prometheus-operator -n monitoring
```

Verify the Prometheus custom resource exists:

```bash
kubectl get prometheus -A
```

# Interview Talking Points

- Deployed Prometheus using the kube-prometheus-stack Helm chart managed entirely through Terraform.
- Implemented Prometheus Operator to manage monitoring resources declaratively.
- Configured persistent storage for Prometheus and Alertmanager using Amazon EBS.
- Enabled Kubernetes default recording and alerting rules.
- Deployed kube-state-metrics and Prometheus Node Exporter for cluster and node visibility.
- Structured the implementation into phases to separate the monitoring foundation from visualization and application-specific observability.
